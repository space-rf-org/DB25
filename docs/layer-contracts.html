How to read this document

A contract here is not documentation for its own sake. It is the golden-fixture schema that drives a single, generic, data-driven test harness: for one input SQL, the expected artifact at every stage boundary. Two things read this spec — a human, to reason about what a layer promises; and the harness, to assert that the layer keeps its promise.

Every Expectation below is written as a falsifiable claim: a concrete input that would make it false. That is deliberate — DB25's testing ethos is Popperian. A claim no test can break is not a contract, it is a wish. Each layer's Enforcement row names the executable guardrail that would catch a violation today, or marks the gap where no guardrail exists yet.

The two halves

Declarative (this doc): readable in one place, good for reasoning and onboarding — but inert. Executable (grammar + corpus + property/metamorphic/conformance suites, gated by the mutant catalog): always enforced, never stale — but implicit. The strongest setup is both, with each clause pointing at the guardrail that enforces it. DB25 has the executable half thoroughly and only fragments of the declarative half; closing that gap is the purpose of this document.

The contracts

Per-layer input → output

Each stage is a pure transform over the artifact to its left. A stage fixes only its own internals and reports cross-boundary issues as contract findings — it never silently absorbs an upstream bug. Stage index encodes pipeline order; the order carries meaning.

T0→T1

Tokenizer

db25-sql-parser · external/tokenizer
Responsibility

Lex raw SQL text into a flat, positioned token stream. No grammar, no nesting.

Input

std::string_view — arbitrary UTF-8 SQL source, well-formed or not.

Output

A token vector; each token carries kind, source span [start,end), and canonical text.

; s-expr fixture shape
(tokens
  (kw      "SELECT" 0 6)
  (ident   "a"      7 8)
  (op      "::"     8 10)
  (kw      "int"    10 13))
Expectations
  1. Total. Every byte of input is covered by exactly one token or an explicit error token; spans are non-overlapping and monotonic.
  2. Lossless. Concatenating token texts + skipped-trivia reconstructs the source (round-trip identity).
  3. No classification of meaning. rollup is an identifier here; whether it is a keyword is the parser's call, not the lexer's.
Non-goals

Balancing, precedence, or validity. A garbage stream still tokenizes.

Enforcement

have tokenizer unit suite + span round-trip. gap no s-expr golden for the token stream yet.

T1→T2

Parser

db25-sql-parser
Responsibility

Build a faithful, untyped AST in an arena. Deliberately permissive: parser-accepts ≠ stack-accepts.

Input

Token stream (T1).

Output

Arena-allocated AST. Every node carries a NodeType, ordered children, and its source span. Precedence and associativity are resolved here and only here.

; -a::int  — :: binds TIGHTER than unary minus
(unary "-"
  (cast (col "a") (type "int")))
Expectations
  1. Grammar-faithful. Accepted input is exactly the EBNF surface (DB25_SQL_GRAMMAR.ebnf + ebnf_supported.sql); the AST shape is stable and pinned.
  2. Precedence-correct. Postfix ::, [], COLLATE bind tighter than unary ±; no operand is silently dropped. open: audit F1
  3. Total & bounded. Any input either yields an AST or a diagnostic with a span — never a crash, never unbounded recursion (DepthGuard).
  4. No lowering, no typing. The parser never resolves names or types; it preserves what was written, including forms the stack will later reject.
Non-goals

Catalog resolution, type inference, semantic legality. Those belong to T3.

Enforcement

have parser unit suites pin AST shapes; EBNF corpus. gap precedence table not exhaustively fixtured — F1 slipped through.

T2→T3

Analyzer

db25-semantic-analyzer
Responsibility

Resolve names against the catalog and annotate the AST in place — types, nullability, resolved table/column ids — while emitting diagnostics. The output is the same tree, now resolved.

Input

AST (T2) + a catalog snapshot.

Output

A resolved AST (annotations layered onto T2, not a new tree) plus an ordered diagnostic list. Naming note: this is the "resolved / annotated AST," not a separate "analyzed-AST".

; SELECT name + name FROM users   (name is TEXT)
(binop "+"
  (col "name" :type text :null true :tid 1 :cid 2)
  (col "name" :type text :null true :tid 1 :cid 2)
  :type unknown            ; NOT text
  :diag (type-mismatch))    ; open: audit F2
Expectations
  1. Sound typing. Arithmetic on a non-numeric, non-temporal pair is a TypeMismatch, not a bogus type. open: audit F2
  2. Reference-faithful promotion. Numeric promotion matches the reference lattice (int < bigint < decimal < double; numeric+real → double). open: audit F4
  3. Consumes the parser's shape fully. Every node kind the parser can emit is handled — incl. GroupingElement for ROLLUP/CUBE. open: audit F3
  4. Deterministic diagnostics. Same input → same diagnostics, same order, same severities; no duplicates.
  5. Documented divergences are intentional & tested. e.g. constant 1/0 is a soft warning, preserved — not a hard error (differs from PG by design).
Non-goals

Plan shape, join lowering, rewrite. It annotates; it does not restructure.

Enforcement

have corpus.tsv per-statement parse/analyze golden; test_analyzer. gap arithmetic-soundness & grouping-element cases unpinned — F2/F3/F4.

T3→T4

Binder / Planner

db25-logical-plan
Responsibility

Lower the resolved AST into a logical algebra tree (LogicalOp): scans, joins, filters, projections, aggregates, set-ops, recursive CTEs. Resolve column references to positional slots.

Input

Resolved AST (T3). Binds defensively — produces a plan even when the analyzer reported errors.

Output

A LogicalOp tree with a well-defined output schema at every node.

(project [ (colref 0) (colref 1) ]
  (filter (gt (colref 0) (lit 100))
    (scan users)))
Expectations
  1. IR well-formed. Every ColumnRef.input_index is in range for its operator's input frame; no dangling OuterRef (scope/depth accounting holds).
  2. Width consistency. Per operator: Project = expr count; ON-join = left++right; Semi/Anti = left width; Aggregate = keys + aggregates; set-op branches share width.
  3. Faithful to T3 types. A node's output type/nullability equals what the analyzer resolved; no lossy re-typing (e.g. no >INT64_MAX decimal → double).
  4. Every supported feature lowers. A construct that parses and analyzes must appear as a LogicalOp — it may not silently vanish between stages.
Non-goals

Rewrite / cost / physical choice. The binder produces a correct plan, not a good one.

Enforcement

have test_binder, test_expr_lower, property-suite IR invariants, conformance stage-propagation. gap no s-expr plan golden per fixture.

T4→T5

Optimizer

db25-logical-plan
Responsibility

Rewrite the logical plan into an equivalent, better logical plan: predicate pushdown, column pruning, subquery decorrelation, and friends.

Input

Logical plan (T4).

Output

A rewritten LogicalOp tree — same output schema, same result multiset, ideally cheaper.

Expectations
  1. Semantics-preserving. bag_equal(eval(bound), eval(optimized)) wherever the reference evaluator supports both — the result multiset never changes.
  2. Shape-preserving. The root output schema (column count, per-column type & nullability) is identical before and after.
  3. Idempotent. optimize(optimize(x)) == optimize(x); a second pass changes nothing.
  4. Invariant-preserving. Every IR well-formedness rule from T4 still holds after every rewrite.
Non-goals

Physical operators, cost models, execution. No such stage exists yet.

Enforcement

have property suite (equivalence, idempotence, shape) + metamorphic + decorrelation oracle, all under the mutant gate. Strongest-covered layer.

T5→T6

Physical plan / Executor

forward-declared
Status

not built No physical planner and no executor exist today. This row is a placeholder so the fixture schema reserves a column and the s-expr format is designed with the eventual boundary in mind.

Why it matters now

When execution becomes remote, the physical plan (or fragments) must cross a process/network line — a real serialization boundary. That is the one place s-expr stops being redundant and becomes the natural plan/control-plane wire + observability format (tuple data stays columnar/binary).

Worked example · the canonical fixture

§One query, every artifact

A single statement carried through all six boundaries, with the s-expression equivalent at each. This is the reference the fixture schema and the s-expr grammar are drawn from.

Fidelity rule — no vacuous renderings

Each s-expr is a faithful projection of the native artifact, never a toy rendering. It carries everything the artifact holds — NodeType + source spans for the AST; resolved tid/cid, type, and nullability for the resolved AST; positional slot indices + per-node output schema for plans — so it round-trips back to an equivalent artifact. Adopting s-expr as the fixture/wire form does not degrade the in-memory artifacts: the arena AST keeps its full typed richness; s-expr is a view over it, not a replacement.

AST

parser · untyped

NodeType-tagged, children ordered, every node keeps :span. Qualifiers, alias bindings, join kind, literal value preserved — but nothing resolved: no :type, no :tid.

T3

resolved AST

analyzer · annotated in place

The identical tree — same nodes, same spans — with attributes layered on: :tid/:cid, :type, :null, plus the stmt :out schema and :diags. s-expr adds keywords; it never collapses structure into a bare type.

(select-stmt :span (0 85)
  :out ((name text :null t) (total double :null t)) :diags ()
  (select-list :span (7 22)
    (column-ref :span (7 13)  :qualifier "u" :name "name"  :tid 1 :cid 2 :type text   :null t)
    (column-ref :span (15 22) :qualifier "o" :name "total" :tid 2 :cid 3 :type double :null t))

          (column-ref :span (65 69) :qualifier "u" :name "id"      :tid 1 :cid 1 :type int :null f)))))
  (where :span (70 85)
    (binary :span (76 85) :op "=" :type bool :null f
      (column-ref :span (76 80) :qualifier "u" :name "id" :tid 1 :cid 1 :type int :null f)

T4

logical plan

binder

Algebra, not the AST. Column refs become positional colref N into each operator's input frame; every node carries its :out schema. WHERE → filter; ON → the join :pred. Join frame [0 u.id, 1 u.name, 2 o.id, 3 o.user_id, 4 o.total].

(project :out ((name text :null t) (total double :null t))
  :exprs ((colref 1) (colref 4))
  (filter :pred (= (colref 0) (int 42))
    :out ((u.id int :null f)(u.name text :null t)(o.id int :null f)(o.user_id int :null t)(o.total double :null t))
    (join :kind inner :pred (= (colref 3) (colref 0))
      :out ((u.id int :null f)(u.name text :null t)(o.id int :null f)(o.user_id int :null t)(o.total double :null t))
      (scan :rel users  :tid 1 :out ((id int :null f) (name text :null t)))
      (scan :rel orders :tid 2 :out ((id int :null f) (user_id int :null t) (total double :null t))))))
T5

optimized plan

optimizer

Two rewrites visible in the diff: predicate pushdown (u.id=42 sinks into the users scan, top filter removed) and column pruning (orders.id dropped). Frames re-index: [0 u.id, 1 u.name, 2 o.user_id, 3 o.total].

(project :out ((name text :null t) (total double :null t))
  :exprs ((colref 1) (colref 3))
  (join :kind inner :pred (= (colref 2) (colref 0))
    :out ((u.id int :null f)(u.name text :null t)(o.user_id int :null t)(o.total double :null t))
    (scan :rel users  :tid 1 :pred (= (colref 0) (int 42))     ; ← pushed down
          :out ((id int :null f) (name text :null t)))
    (scan :rel orders :tid 2                                    ; ← id pruned
          :out ((user_id int :null t) (total double :null t)))))

What the six columns assert — for free

  • root :out is byte-identical across T3 → T4 → T5 → shape-preservation holds.
  • optimize a second time reproduces T5 verbatim → idempotence.
  • every colref N is in range for its node's :out width → IR well-formedness.
  • bag_equal(eval(T4), eval(T5)) → semantics-preservation.

The harness the contracts feed

§Staged-artifact test framework

One generic engine, one fixture corpus, two modes. The contract above defines what each fixture column must contain; the harness asserts each stage produces it.

Two modes over the same fixtures

End-to-end

Run the whole pipeline; assert every intermediate s-expr equals its golden and the final bag is correct. Pinpoints the first diverging stage — correctness by evidence at each seam, not just final rows.

Per-module (isolation)

Feed a stage its input artifact directly (needs s-expr readers) and assert its output. Isolates which stage is wrong, and lets you inject ASTs/plans the SQL parser might never produce.

Why s-expr — and its limits

One format serves three jobs: golden fixture, debug dump, and (later) the remote plan wire format. It is homoiconic, diff-able, git-friendly, and trivial to parse in any worker language.

Scope it deliberately. s-expr is the test/serialization boundary and the future control-plane format — not the runtime interchange (in-memory typed structs stay; serialize-then-reparse on the hot path is pure cost) and not the data plane (tuples ship columnar/binary). Writers are cheap (~1 artifact each, reuse dump_plan); readers roughly double the effort but unlock per-module mode.

Falsifiability & the differential oracle

  • Mutant gate. Every golden must fail against ≥1 entry in the mutant catalog. A fixture that survives all mutants is vacuous and is itself rejected — a green suite therefore means something.
  • External oracle, scoped. Tally accept/reject + type/nullability against libpg_query (and later DuckDB) as a boundary oracle — high signal for exactly the F2/F3-class bugs. Do not diff ASTs tree-to-tree: node vocabularies differ, mapping is brittle, and intentional divergences (e.g. 1/0) become noise. Divergences live in a curated allow-list, as the corpus already does.

Sequencing

§What we build, in order

Documentation and schema first; writers + end-to-end mode next (fast, high value); readers + per-module mode second; oracle last. No production code changes.
